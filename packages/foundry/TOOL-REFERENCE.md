# Tool reference

The tool list carries short routing guidance. This guide preserves the detailed contracts and limits for each tool. Full input validation schemas are available through MCP resources at `oods://schemas/<tool_name>.input.json`; relative JSON Schema references are readable under the same prefix. These full schemas remain the server validators; the compact tool-list schemas are discovery summaries.

## tokens_build

Build the current brand-registry source with the shipped compiler kit and server dependencies. apply:true compiles in an isolated artifact directory, returns requested-brand/theme CSS variables, CSS and JSON inline, and writes five artifacts with paths, hashes and sizes. Full CSS includes all registered scopes; TypeScript and Tailwind retain A/light defaults. Source and shipped runtime files are never changed. Without apply it lists the artifacts it would create and writes nothing, including no run record. A missing compiler kit returns OODS-N011; a failed compiler returns OODS-S019 with its output.

## structured_data_fetch

Fetch live components, objects and traits (including registered team definitions; business objects, with OODS Foundry's internal objects only when includeInternal is true and registry.hiddenInternal counting the ones left out), or archived tokens/manifest data or a Stage1 run's artifacts via kind+runPath: the rollups (identity_graph, capability_rollup, object_rollup, drift_report 1.0.0–1.4.0) and the run-view kinds at their pinned versions — a11y_report 2.2.0–2.5.0, report_index 1.0.0/1.1.0, a11y_evidence 1.1.0–1.4.0 (every per-page axe file read only when its sha256 matches the run manifest's attestation) and run_manifest (historical unstamped shape or schema_version 1.0.0 through 1.7.0; a suite's root, which records its targets, is refused). Any other version is refused rather than parsed. In dataset mode it computes a canonical payload ETag and honours ifNoneMatch consistently across paths; a mismatched manifest ETag warns and malformed manifest JSON returns OODS-S005, meta.source distinguishes live-registry from committed-export; version pins a dated export (the nearest earlier one, with a warning, when that date has none) and listVersions lists the dated exports; listVersions and version are dataset-only; supplying them in kind mode returns structured_data_fetch-specific OODS-V202. The separate derived_analysis kind admits manifest.analysis analysis 1.0.0/1.1.0, run_manifest 1.0.0–1.7.0, drift_report 1.0.0–1.4.0, report_index 1.1.0 and fig_local_tokens version 1.0.0/1.3.0/1.5.0 after retained-file digest, confined realpath, lineage, identity/time and JSON-pointer checks. A derived analysis is never a captured run; an optional recomputed fingerprint requires its declared pass, output and source-digest lineage. Copied inputs are not rerun; drift_report 1.3.0 and 1.4.0 ratios are different measurements.

## brand_apply

Apply brand token overlays to a brand's canonical source using alias strategy or the supported add/remove/replace subset of RFC 6902. Requires a delta object. apply=true writes source, runs both real token-build stages, and returns before/after SHA256, byte counts and captured build results. The brand as the change would leave it is checked first, as brand_create validate checks a brand: apply:true writes nothing unless it validates (OODS-V216), and a dry run returns the report. The receipt lists each changed slot. Build failure returns OODS-S019 with the last 40 output lines; source writes remain in place. After the build, the review kit's variables.css holds the CSS variables the build emitted differently, under their selectors. Default dry-run writes no files, directories, transcripts or bundle indexes. Only apply writes its run record. The brands are the brand registry's: the brands folder the token build reads (A and B ship; health_check lists them). A brand of yours (in OODS_BRANDS_DIR; from npm ~/.oods-foundry/brands) is written and rebuilt there, from npm too. For the brands OODS Foundry ships, the runtime bundle ships the brand source, so apply:false previews from the bundle; there apply:true emits the review kit (snapshots and specimens) without writing source or rebuilding, and the receipt records both steps as skipped. OODS-N020 is returned only when the brand source directory is missing.

## brand_create

Create a brand from your own token values or from a recipe. Set `action` to template (every slot of the light, dark and high-contrast themes with its meaning and a starting value: brand A's, another brand's with from.brand, or a shipped preset over it with from.preset; or, with from.recipe, the complete brand a recipe gives, graded: a recipe is neutralHue, neutralChroma, accentHue, primary "neutral" or "accent", radius and font, and every colour, radius and font stack follows from it), validate (check filled documents, or a recipe, and report every problem: missing or unknown slots, types, colours that do not parse, and the brand contrast rules, 84 pairs in light, dark and high contrast: text at 4.5:1, and status icons, control borders and the focus ring at 3:1, and in every theme the chart marks, the one-series colour and the six series at 3:1 on the canvas, each failing one saying whether its value is brand A's; writes nothing; OODS Foundry computes the sha256 and bytes of the files create would write) or create (write a brand that validates, from documents or a recipe, into the brands folder and run the token build, so every tool and the preview can use it at once; it never replaces a brand, OODS-C005, and a brand that does not validate is refused with the report, OODS-V216). From npm, create writes into your brands folder (~/.oods-foundry/brands, OODS_BRANDS_DIR) and builds it there, outside the runtime; with no brands folder set, only a source checkout can create (OODS-N025). derive accepts exactly one of tokens (your DTCG document), css (shadcn theme CSS text), or cssPath (an absolute CSS entry path), with optional hints for accent, neutral, radius, font or fontMono. It resolves local aliases and derives a partial six-value recipe, per-value provenance, named gaps and warnings without writing or filling missing values. Pass the reviewed recipe to create after filling gaps. Generated dark and high contrast still undergo the same checks; your token names are not carried into generated apps.

## design_compose

Compose a UiSchema from an object and a context, or from a short intent sentence matched against fixed keyword and phrase tables: a sentence that matches no layout keyword uses the dashboard default without numeric confidence (OODS-V116) with no object, so naming an object and a context is the reliable input. Returns schemaRef for reuse in validate/render/code_generate. schemaRef includes createdAt/expiresAt timestamps (default TTL: 30 minutes) and lives in the server process that issued it: a restarted client starts a new server that does not know earlier refs and returns OODS-N003 for them. To keep a screen beyond the TTL or across sessions, save it with schema_store (action: save) and load it by name (action: load). Every successful composition is recorded as a durable version (compositions/<compositionId>/versions/<n>.json beside the saved-schema store) and the result carries compositionId, version, parentVersion, operation and head; pass compositionId to record the result as that composition's next version, or options.transient to record nothing. design_preview opens any version at /preview/<compositionId>/<version>. preferences.regionOrder, preferences.fieldOrder and preferences.seed are the override surface edits re-compose through; the seed is recorded on the schema and rotates the deterministic sample data. Selected OODS Foundry nodes snapshot active substitution mappings; meta.substitutions lists affected nodes. A saved snapshot retains its mapping even if the user store changes. Component selection remains based on OODS Foundry traits. Explicit placements omit confidence; keyword rankings report their computed scores and warnings. Selections describe only surviving slots. Validation failures and unloadable objects return errors.

## dashboard_render

Render a composed metric-overview dashboard (KPI row + trend + breakdown + optional geo map) from a declarative DashboardSpec of shared datasets + panels. Composes each panel through the in-process viz engine with deterministic auto-layout and headless KPI compute, and applies a caller-supplied cross-filter selection at render time (declared links render as a labelled reference list; filtering uses selection and crossFilter). KPI tiles in HTML draw their computed sparklines and labelled breach/anomaly markers. Returns the resolved layout, per-panel compiled specs (Vega-Lite or ECharts, geo registration preserved), KPI values, a dashboard-level a11y block, and one specRef for pipeline reuse.

## artifact_certify

Certify the OODS Foundry NormalizedVizSpec returned by viz_render. Returns coverage, a measured conformant result, findings, and four pillars: a11yEquivalence, determinism, contrast and accuracy. Read-only: it reads the IR and the matching data operand without rebuilding or recommending a chart.

DECLARED COVERAGE. The five Cartesian types certify from the IR alone. The eight ECharts-primary types certify under the declared operand profile when the same data branch used by viz_render is supplied. ECharts conformance requires a11yEquivalence:'pass', contrast neither 'fail' nor 'ungradeable', stable determinism, and accuracy:'pass' with rulesEvaluated > 0 and no detected distortion. A certified chart can be conformant:false; inspect the pillars and findings. No Vega-Lite compile is added to the ECharts profile. Spec-only ECharts calls remain coverage:'uncertified' with conformant:null and notes naming the missing operand. Unmodeled marks remain explicitly uncertified.

DATA. An ECharts-primary IR carries metadata; nodes, links, rows and geometry live in its original branch. Supply exactly the matching hierarchy, sankey, chord, network or geo branch as data. The tool validates it against the mark trait. Data on a Cartesian IR is OODS-V123 because those charts certify from their IR. HTML or invalid IR is OODS-V126.

ACCESSIBILITY. The 16 equivalence rules evaluate the operand-built table and narrative. Error-severity failures fail the ECharts pillar and conformance. Warnings stay visible without failing the pillar. Findings keep their native severity. a11yNotApplicable lists rules whose declared preconditions were absent; absence is not a meaningful pass. This channel is present when the ECharts engine completed, including [] if no rule was inapplicable, and absent for spec-only, Cartesian or incomplete engine evaluations. A completed engine with an individual rule fault retains its findings and not-applicable results while failing the pillar. An evaluator fault cannot produce a passing accessibility pillar.

ACCURACY. Cartesian rules read the IR and compiled spec: non-zero bar baseline (V150), dual axis (V151), area scaling (V152), undisclosed aggregation (V153). ECharts rules read data: invalid hierarchy values/non-additive parents (V154/V155); invalid sankey/chord link values (V156); inconsistent sankey node throughput/duplicate links (V157/V158); conflicting choropleth join values (V159); negative or non-finite bubble size (OODS-V168), radius-based bubble scaling (OODS-V169), conflicting rows at the same bubble coordinates (OODS-V170), negative or non-finite flow strength (OODS-V171), duplicate directed geographic flows (OODS-V172), and duplicate directed force-graph links (OODS-V173). Reciprocal graph links and reciprocal geographic flows are distinct. Bubble scaling measures numeric diameters on the built projected ECharts option against area ratios from zero; missing drawn sizes are unresolved, and certification does not repair pixels. accuracyRules lists offered codes, while accuracySummary counts only rules whose preconditions resolved. Pass means no offered rule detected its distortion, not a general promise of accuracy; zero evaluated ECharts rules is unchecked and cannot yield conformant:true.

DETERMINISM. Two independent compiler/adapter emissions are compared and rendered independently. contentHash identifies the first canonical compiled spec or projected ECharts option; renderHash identifies its normalized SVG and matches viz_render for the same operand/scope. Stable requires both identities to repeat. A first-render fault keeps contentHash, omits renderHash and fails stability. A bubble_map without inline geometry keeps the option proof, omits renderHash and names the no-server-map limitation. Proof is bounded by packages/viz-render/certified-matrix.json and covers certify's own rendering, not a caller's rendering.

CONTRAST. Cartesian charts and ECharts calls with data grade actual rendered paints. Role C checks mark-to-canvas WCAG 3:1; Role A checks categorical CIEDE2000 distinguishability across normal vision and three CVD simulations, retaining recycled-palette duplicates. Missing baked OODS palette bytes cannot produce contrast:'pass'. The three geo families retain the standing contrast exemption with their render evidence; this includes ordinal bubble maps. Spec-only ECharts calls retain the reconstructed palette grade and caveat. Cartesian conformance still fails for fail or ungradeable contrast/accuracy; unchecked and exempt retain their existing semantics. Read every pillar's enum, including ungradeable. contrastResults reports the requested theme/brand and measurement evidence; exemptions do not claim a canvas ratio.

SCOPE. Theme light|dark|hc and a brand in the brand registry select the same CSS scope as rendering, default light/A. HC contrast returns exempt, measured:false and reason:forced-colors, with no numeric grade. Accessibility, accuracy and determinism retain their normal evaluation; an actual HC render failure fails determinism and conformance.
