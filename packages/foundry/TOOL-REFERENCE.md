# Tool reference

The tool list carries short routing guidance. This guide preserves the detailed contracts and limits for each tool. Full input validation schemas are available through MCP resources at `oods://schemas/<tool_name>.input.json`; relative JSON Schema references are readable under the same prefix. These full schemas remain the server validators; the compact tool-list schemas are discovery summaries.

## tokens_build

Build the current brand-registry source with the shipped compiler kit and server dependencies. apply:true compiles in an isolated artifact directory, returns requested-brand/theme CSS variables, CSS and JSON inline, and writes five artifacts with paths, hashes and sizes. Full CSS includes all registered scopes; TypeScript and Tailwind retain A/light defaults. Source and shipped runtime files are never changed. Without apply it lists the artifacts it would create and writes nothing, including no run record. A missing compiler kit returns OODS-N011; a failed compiler returns OODS-S019 with its output.

## structured_data_fetch

Read the live components dataset (including registered team objects and traits), archived token/export datasets, or Stage1 artifacts. Dataset reads preserve full output by default. For clients without access to the server filesystem, start with `{ "dataset": "components", "detail": "summary" }`, then call `meta.next` unchanged until absent. Pages carry lossless `{path,value}` entries using JSON Pointers; apply them in order to reconstruct the full object. Each page is below 100,000 characters. `pageSize` defaults to 10 and accepts 1–100, also bounded by serialized size. `meta.full` requests the complete file; `payloadMode:"inline"` requests the complete inline payload explicitly. Projection-specific ETags prevent a summary or previous page from suppressing a different page. `includePayload:false` omits the current payload; next/full calls still request data.

`includeInternal` includes internal objects; otherwise `registry.hiddenInternal` counts them. `version` pins a dated export (nearest earlier with a warning if absent), and `listVersions` lists dates. These and paging/detail are dataset-only; kind mode refuses them with OODS-V202. `meta.source` distinguishes live registry and committed export.

Stage1 is an optional capture tool, published separately. `kind` plus `runPath` reads its retained artifacts: run_manifest through 1.8.0, a11y_report 2.2.0–2.5.0 and 3.0.0, drift_report 1.0.0–1.4.0 and 2.0.0, report_index 1.0.0/1.1.0, and a11y_evidence 1.1.0–1.4.0, alongside the existing identity/capability/object rollups. The derived_analysis kind admits analysis 1.0.0/1.1.0, fig_local_tokens 1.0.0/1.3.0/1.5.0/1.6.0 and recomputed style_fingerprint 1.3.0/1.4.0. Retained-file hashes, confined paths, lineage and JSON Pointers are checked. Unknown versions and suite roots refuse with accepted versions named. Earlier admitted versions remain readable. Missing accessibility scores stay absent; drift 1.4.0/2.0.0 raw observations do not become invented token identities or regraded severity.

## brand_apply

Apply brand token overlays to a brand's canonical source using alias strategy or the supported add/remove/replace subset of RFC 6902. Requires a delta object. apply=true writes source, runs both real token-build stages, and returns before/after SHA256, byte counts and captured build results. The brand as the change would leave it is checked first, as brand_create validate checks a brand: apply:true writes nothing unless it validates (OODS-V216), and a dry run returns the report. The receipt lists each changed slot. Build failure returns OODS-S019 with the last 40 output lines; source writes remain in place. After the build, the review kit's variables.css holds the CSS variables the build emitted differently, under their selectors. Default dry-run writes no files, directories, transcripts or bundle indexes. Only apply writes its run record. The brands are the brand registry's: the brands folder the token build reads (A and B ship; health_check lists them). A brand of yours (in OODS_BRANDS_DIR; from npm ~/.oods-foundry/brands) is written and rebuilt there, from npm too. For the brands OODS Foundry ships, the runtime bundle ships the brand source, so apply:false previews from the bundle; there apply:true emits the review kit (snapshots and specimens) without writing source or rebuilding, and the receipt records both steps as skipped. OODS-N020 is returned only when the brand source directory is missing.

## brand_create

Actions: `create`, `draft`, `apply`.

Create a brand or stage a local token intake draft. Use it when adding a brand; use brand_read for templates, validation, derivation and draft review, or brand_apply to edit a brand. Returns a staged draft or created brand with build results. apply needs draftId and accept:true. create accepts filled documents or a recipe, validates all themes, refuses replacement and removes a brand whose build fails. Full schema: oods://schemas/brand_create.input.json.

## catalog_list

List available OODS components from the live component-contract registry, with current trait usages and registry object/trait names including team definitions: business objects first, OODS Foundry's internal objects only when includeInternal is true, and registry.hiddenInternal counting the ones left out. Historical readiness evidence is retained with its original provenance. Filter by category, trait, or rendering context. Response includes availableCategories array showing all valid category values for filtering. Unfiltered, it answers briefly: each component's name, categories and one readiness label (proven-in-generated-apps when a runtime sweep's generated app used it, the sweep its evidence names; react-and-vue; or incomplete); detail summary adds tags, contexts, regions and traits, and detail full adds the evidence. Filtered calls with no explicit detail now default to full detail in pages of 10. Unfiltered calls keep their bounded brief default. `totalCount`, `returnedCount` and `nextPage` make truncation explicit; pass `nextPage` unchanged for the next response. `pageSize` is at most 100. An explicit `detail` without paging preserves the previous unpaged response.

Missing or malformed edge fields fail closed. VizGraphPreview embeds the exact public SVG inside a named wrapper. React/Vue application output is supported. HTML shares its record renderer with schema_render document output: labelled native form controls, local list search/filter/sort/pagination, keyboard tabs, charts and selectable workflow screens and loading/error/empty/success states. Domain actions display an integration notice and never claim a saved, deleted or navigated record. React/Vue substitution uses the mapped package export and translated normalized props for single screens and workflows. Artifact substitutions record mapping identity and exact package versions; install steps name the team dependencies. An explicit mapping version or an installed package manifest is required. Mapped team components receive advisory componentContracts reports from the shared contract scenarios through the generated adapters. For HTML, application output is the same standalone document. The default remains component output for React/Vue; their workflows already emit apps. A generated app installs its @oods packages from npm, at the exact versions the install block names. Domain actions show a visible integration notice until the consumer supplies its handler; no backend change is fabricated. Sample fields use authored examples/defaults/enums or neutral typed values. ## design_compose

Compose a UiSchema from an object and a context, or from a short intent sentence matched against fixed keyword and phrase tables: a sentence that matches no layout keyword uses the dashboard default without numeric confidence (OODS-V116) with no object, so naming an object and a context is the reliable input. Returns schemaRef for reuse in validate/render/code_generate. schemaRef includes createdAt/expiresAt timestamps (default TTL: 30 minutes) and lives in the server process that issued it: a restarted client starts a new server that does not know earlier refs and returns OODS-N003 for them. To keep a screen beyond the TTL or across sessions, save it with schema_store (action: save) and load it by name (action: load). Every successful composition is recorded as a durable version (compositions/<compositionId>/versions/<n>.json beside the saved-schema store) and the result carries compositionId, version, parentVersion, operation and head; pass compositionId to record the result as that composition's next version, or options.transient to record nothing. design_preview opens any version at /preview/<compositionId>/<version>. preferences.regionOrder, preferences.fieldOrder and preferences.seed are the override surface edits re-compose through; the seed is recorded on the schema and rotates the deterministic sample data. Selected OODS Foundry nodes snapshot active substitution mappings; meta.substitutions lists affected nodes. A saved snapshot retains its mapping even if the user store changes. Component selection remains based on OODS Foundry traits. Explicit placements omit confidence; keyword rankings report their computed scores and warnings. Selections describe only surviving slots. Validation failures and unloadable objects return errors.

## pipeline_run

It forwards draft, build, or release generation validation without downgrade and always discloses the applied validationReceipt plus target resolution provenance. The code step carries the versioned artifact without flattening, including exact dependencies and required consumer-supplied domain actions. Defaults to compact render mode (token CSS omitted). Supports optional validation/render skipping, an optional static screen and built-scope contrast check (options.checkA11y; unresolved pairs remain unmeasured), and schema persistence via save parameter. ## registry_snapshot

Return in one call recorded mappings plus the active shipped and registered team traits and objects, with a canonical ETag and generatedAt. Objects are the business objects; OODS Foundry's internal objects are included only when includeInternal is true, each object carries its visibility, and registry.hiddenInternal counts the ones left out. registry states the live source, names and loader issues, including the shadowed shipped Subscription. Draft preferred_terms, disambiguation_decisions and capabilities remain historical mapping storage fields and are not advertised as snapshot capabilities. ## viz_render

Render a real, data-bound visualization spec from inline rows (or a datasetRef). Four input modes: supply pattern with an exact catalog id (for example pattern:viz:simple-bar) to render its bundled rows, encodings and presentation; supply chartType+encodings for explicit mode; omit chartType for recommender-driven suggest mode; OR supply a structured `intent` {goal, measures[], dimensions[], chartFamily?, measureRef?} (instead of chartType/encodings — the deterministic half of NL→viz) where the named fields drive encoding, the goal+data drive the recommender pick, an optional chartFamily post-filters it, and an optional governed measureRef lights the measure narrative under output.includeA11y. Returns spec for the five tabular Vega-Lite families (additional ECharts output opt-in). The eight ECharts-primary families return echartsSpec with spec omitted and output.echarts:true plus reason:echarts-primary-family, even if the caller passed false with a synthesized a11y description; compact by default with a specRef trio for pipeline reuse. Supports 13 chart types: 5 tabular (bar, line, area, scatter, heatmap) in suggest/explicit/intent mode, plus 8 explicit-only (treemap, sunburst, sankey, force_graph, chord, choropleth, bubble_map, flow_map). On the CARTESIAN color channel you may supply an explicit `encodings.color.range` — an array of 2+ hex colors (e.g. ["#1F6FEB","#D1242F"]) applied in order to the distinct series, overriding the baked OODS categorical palette (e.g. a 2-color presence scale). Cartesian nominal/ordinal color only: a range on a non-color channel is rejected, on an ECharts-primary type (treemap/sankey/etc.) fails loud (OODS-V145), and on a continuous color scale is ignored with a warning. certify grades the supplied range exactly as it grades the palette, so a low-chroma or low-contrast 'absent' color truthfully fails the contrast pillar — prefer chromatic colors above the chroma floor. For the categorical ECharts-primary types (treemap/sunburst/sankey/force_graph/chord), more distinct color groups than the 6-slot OODS palette recycles a color across two groups and is surfaced as a never-cycle warning (OODS-V146). For chord and force_graph link integrity, a link naming a node that does not exist fails loud (OODS-V147), and a duplicate directed (source,target) link — chord/force_graph are directed, so A→B and B→A are distinct — is surfaced as a warning (OODS-V148).

SCOPE. theme (light|dark|hc, default light) and brand (a brand in the brand registry, default A) resolve the generated CSS token scopes for chart pixels. Omission equals explicit light/A. Scope changes chart content and SVG hashes. HC emits the scope declarations verbatim, including Canvas/CanvasText; computed paints are verified under forced-colors browser emulation. HC heatmaps use nine declared quantized steps with symbol legends; numeric geo color uses declared piecewise steps. The paint guard still returns OODS-V165 if a renderer substitutes an undeclared paint. No server-side system-color hex palette is invented. Series retain the light palette where tokens declare no theme-specific palette. PATTERNS. The 22 offered source identities render public SVG with four conformant light/dark and A/B scopes; linked-brush-scatter is retired and not offered (the viz taxonomy records its reason and the correlation-scatter alternative): the input schema refuses it with OODS-V001, and a caller that skips the schema gets OODS-V174. Scenes preserve layers, bounded facets and secondary axes. Static SVG shows the default selection state (OODS-V175); transforms, datasets, external data and unknown traits remain structural limits (OODS-V167). Combining pattern with explicit data, encodings, intent or identity/presentation overrides returns OODS-V166. Brand, theme, strictFields and output controls remain available; authored source data and presentation are bundled for portable rendering. <!-- history -->

## dashboard_render

Render a composed metric-overview dashboard (KPI row + trend + breakdown + optional geo map) from a declarative DashboardSpec of shared datasets + panels. Composes each panel through the in-process viz engine with deterministic auto-layout and headless KPI compute, and applies a caller-supplied cross-filter selection at render time (declared links render as a labelled reference list; filtering uses selection and crossFilter). KPI tiles in HTML draw their computed sparklines and labelled breach/anomaly markers. Returns the resolved layout, per-panel compiled specs (Vega-Lite or ECharts, geo registration preserved), KPI values, a dashboard-level a11y block, and one specRef for pipeline reuse.

PANEL IDENTITY. Every successful chart panel returns the contentHash produced by its in-process viz_render call; it therefore matches a standalone viz_render call with the identical spec and data. Set the call-level output.includeNormalizedSpec flag to also return each successful chart panel's NormalizedVizSpec. That IR can be passed to artifact_certify as {spec} alone for a cartesian chart, or as {spec,data} with exactly the matching hierarchy, sankey, chord, network, or geo branch for an ECharts-primary chart. These per-panel identity fields are attached after the dashboard's canonical {panels,layout} projection is cached and hashed, so they do not feed the dashboard contentHash.

HTML IDENTITY. When output.html=true, outputHtmlHash is SHA-256 over the exact returned HTML bytes. It is evidence of deterministic output for that call and runtime, not part of the ECharts certified-matrix/renderHash epoch. ## artifact_certify
